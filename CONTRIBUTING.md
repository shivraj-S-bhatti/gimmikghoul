# Bring an idea or break one

An unusual core, a team report, or a counterexample is a useful contribution. You do not need a winning team or a proof of novelty.

Open an issue with the format and regulation, the idea, what you hope it accomplishes, and the question you want to answer. Include exact sets or a source when available. Explain any matchups you are willing to lose. Missing details can remain open questions.

For a mechanism correction, give the smallest state that demonstrates it and an engine trace or source if you have one. For a new representation, show how a person or agent would use it to make a decision. For a dataset, preserve source terms, authorship, dates and scope.

Use `npm ci && npm test` for the portable checks. Native damage/legality calls require the pinned upstream preparations in the README. Keep secrets, caches and local conversation logs out of commits. The current theory loop assumes one writer per theory; discuss concurrent revisions before editing the same file.

Research proposals belong beside the experiments they could become. Contributors can challenge the project's graph premise as readily as its Pokémon reasoning.
